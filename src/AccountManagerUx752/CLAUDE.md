## Feature flags — accepted debt & decisions

Design of record: `../aiDocs/UxFeatureFlagDesign.md` (§3 findings, §4a D1–D5).

**`src/features.js` must stay dependency-free.** It holds only the non-serializable wiring
(`routes: () => import(...)`, `menuItems`, `routePrefixes`); the data half (`label`, `description`,
`required`, `deps`) lives in `src/features.manifest.json`, a **byte-for-byte copy** of
`AccountManagerObjects7/src/main/resources/features/uxFeatureManifest.json` (which
`GET /rest/config/features/available` serves verbatim). Never hand-edit the copy — copy the Objects7
resource over it; `featureFlags.test.js` asserts the two files are identical. Adding a static
`import { page } from './core/pageClient.js'` to `features.js` would create a real ESM cycle
(`pageClient.js` carries `formDef: am7model`, so it imports `core/model.js`), which is why
`isMenuItemVisible(mi, ctx)`, `visibleCategories(categories)` and `applyFeatures(list, { refresh, … })`
all take their context as arguments instead of importing it. For the same reason `core/model.js` is
deliberately NOT filtered by feature: `am7model.getPrototype` only walks the `identity` and `asset`
categories, both untagged, so filtering there would buy nothing and cost an import cycle.

**Accepted core weight: eager `olio.js` + `gameStream.js`.** `main.js:24` eagerly imports
`am7olio` from `components/olio.js` (658 lines), and `core/gameStream.js` is likewise eager, because
`core/formDef.js` command buttons need `am7model._olio` **synchronously**. This is accepted as core
bundle weight for now — not a bug, a deliberate deferral. Making it lazy is a separate change (it
touches 47 olio references in `formDef.js` and needs its own tests); the pattern it would use already
exists at `src/features/media.js:31-32`, which wires `_olio` through the `lazyComponent` getter. After
D5 the sidebar and `/main` dashboard are clean regardless; only bundle bytes are at stake.

**`core/modelDef.js` is hand-curated, despite its "Generated by AccountManagerService7/rest/schema"
header (`:1-4`).** It diverges from `/rest/schema` in both directions: the server emits six categories
(`CategoryUtil.CATEGORY_NAMES` = identity, asset, process, event, policy, form), while the client file
adds `olio` and `ai` (which exist client-side only) and drops `event` and `form`. A faithful
regeneration would therefore DELETE `olio`/`ai` — along with the `"feature": "cardGame"` / `"feature":
"chat"` tags D5 depends on — and ADD `event`/`form`. Independent proof of hand-editing:
`modelDef.js` contains a `/* … */` comment block inside the `olio` category's `order` array, which no
JSON response can contain. **Follow-up:** either reconcile the file with `/rest/schema` (moving
`feature` onto the `system.modelCategory` model in Objects7) or delete the false "Generated by" header.

**`media` degrades, it does not crash.** `media` is optional; disabling it removes the PDF viewer, SD
config, olio dress system, audio, designer and emoji registrations (`src/features/media.js` registers
**seven** things). Key any user-facing "disabled" messaging on `isEnabled('media')` **only**. Do NOT
add "disabled" text at the guarded call sites (`components/objectViewRenderers.js:144,152`,
`views/list.js:263,314,1105`, `cardGame/designer/designerCanvas.js:308`): `lazyComponent`'s getter
(`src/features/media.js:9-20`) returns `null` on FIRST access and does not `m.redraw()`, so
"not yet loaded" and "disabled" are indistinguishable there and the message would lie during normal
loading. Note also that two of the seven registrations have **no reader anywhere in `src/`** —
`page.components.designer` (`:45-46`) and `page.components.audioComponents` (`:37-38`) — so do not
document a user-visible degradation for those.
